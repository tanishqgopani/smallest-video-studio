# Smallest AI video studio

Built from four videos made with the team and the corrections that came back. Start from an approved look instead of re-deriving it, but **the look is a choice, not a fixed template**: ask for the style and the colours at intake. Read the reference files only when you reach that step.

## The rules that cause the most rework

1. **Never fake a demo.** Audio that stands in for Lightning, Pulse or Atoms must be generated by that product. ElevenLabs is for narration only. If a Smallest key is rejected (`unauthorized`), stop and ask for a new one — don't work around it.
2. **No invented claims.** No benchmarks, accuracy, latency, language counts, customer names, "trained on…" or "millions of…" unless the user states it or the docs say it. If the user states it, use it and flag it as theirs to verify. Show real output on screen instead of made-up numbers.
3. **The background always moves.** A gradient that sits still looks like a screenshot. Use `assets/gradient-bg.js` (moving gradient in any colours, three modes). Compare stills a few seconds apart to confirm motion.
4. **Style and colours are the user's call.** Offer the styles in `references/styles.md` (launch film, light explainer, call demo, data-led demo, brand-colour gradient, type-only poster, plus diagram explainer) and use the colours they give. House rules (no orange, rose for errors) apply only when they pick the house blues. Constants in every style: Aeonik, real logos, minimal, no capsule/pill labels, no underline highlights.
5. **Time every visual from the real audio**, never by eye. Snap word timings to silences (`references/audio-pipeline.md`).
6. **Verify with stills and measurements, then render.** Contact sheets at the beats, silence checks, no overlapping captions, text contrast against the brightest background frame. Say honestly what you checked in stills versus by playing it.

## Workflow

1. **Intake — ask these first, in one message, before building anything:**
   - **Story and length.** What product/idea, which format (recipe below), how long, vertical or horizontal.
   - **Style.** Offer the list from `references/styles.md` in a line each; accept a blend or their own description. If they have a reference video, study it frame by frame (contact sheets + transcript) and copy its pacing and layout, not its colours.
   - **Colours.** "Which colours should the gradient use? Give 2–5 hex codes or names, and say dark or light." Build the gradient from exactly those (`references/styles.md` → Colours from the user). No answer → offer the house blues or three suggestions.
   - **Voice and keys.** Ask for both, and say what each unlocks:
     - `ELEVENLABS_API_KEY` — narration (and nothing that stands in for a Smallest product).
     - `SMALLEST_API_KEY` — Lightning voices for demos, Pulse transcription/timing and checks, voice cloning, Atoms.
     A narration-only film needs just ElevenLabs; anything that demonstrates a Smallest product needs the Smallest key. Keys go inline as environment variables for one command, never into a file, script, log or composition.
   - If the user can't or won't supply a key (or has gone away), don't stall and don't switch vendors silently: build with the placeholder narration (`scripts/placeholder_tts.sh`), label it as a placeholder in the hand-off, and offer to re-narrate and re-time when a key arrives. Ask again for the key in the hand-off.
2. **Script.** Concise, serious, concrete, first person plural where it is Smallest speaking, sentence case, no hype, no exclamation points, no emojis (see the `smallest-copy-style-guide` skill for external copy). Open with the situation or the problem, not the product name. Mark numbers/names/claims you don't have as `[placeholders]` and list what the author must verify. Show the user the script split into beats with a visual idea per beat if they have not already approved one.
3. **Audio.** Generate and trim every clip, then get word/phrase timings (`references/audio-pipeline.md`). Pronunciation: respell in plain words, concatenated; verify with a Pulse round-trip; outputs vary between runs, so generate several takes and keep one that round-trips cleanly. You cannot listen — tell the user to check pronunciation by ear.
4. **Build** a HyperFrames project (`references/hyperframes-build.md`): copy `assets/` (fonts, logos, grain, `gradient-bg.js`), start from the nearest file in `examples/`, set the gradient to the user's colours, drive every beat from the audio times.
5. **Check, render, compress, deliver.** `check` → `snapshot` at the beats → fix → `render` (60 fps for motion-heavy pieces, 30 otherwise) → ffmpeg crf ≈ 22 share copy → send the file. Then offer the caption.
6. **Caption** for posting: see "Captions" below.

## Format recipes (full detail in `references/video-recipes.md`)

| Recipe | Example file | One-line shape |
|---|---|---|
| Launch / entities film | `examples/entities-launch.html` | problem → "Introducing X" → what it does → dictionary/feature → CTA → logo |
| Diagram explainer | `examples/concept-explainer.html` | one visual idea per sentence (bars that add up, a block bolted on, a stack collapsing, signal flowing through) → logo |
| Voice-agent call with live transcript | `examples/call-with-live-transcript.html` | photoreal phone + iOS call UI + diarized transcript card, spoken IDs/amounts that merge into written form |
| Voice-clone quiz ("Which voice is the real one?") | `examples/voice-clone-quiz.html` | white, two spectrum columns, alternating lines, reveal, white→black end card |
| Speech-to-text short-words demo | `examples/short-words-stt.html` | long rambling answer ending on one tiny word, then six real Pulse results, phone-line replay |
| Type-only teaser | build from `concept-explainer.html` | huge type, few words per beat, slow `flow` gradient, logo |

## Captions (social)

First line is one word or one clear statement. Then the problem in concrete terms (one wrong digit sends money to the wrong branch), then what the product does. Name the real products (Pulse hears, Electron decides, Lightning says) only with claims the user confirms. No "BFSI" in public copy — say banking and finance. End with `[Link]`. Offer a short X version. List every claim the author must verify.

## Files

- `references/styles.md` — the style menu, how to turn user colours into a gradient, quick chooser.
- `references/design-system.md` — house palette, type, motion, layout rules, snippets (spectrum bars, masked reveals, handheld camera).
- `references/audio-pipeline.md` — TTS, cloning, pronunciation dictionaries, STT, diarization, timestamp snapping, spectra, no-key fallback.
- `references/hyperframes-build.md` — project setup, determinism, lint gotchas, snapshot/render commands, footage enhancement, photoreal phone.
- `references/video-recipes.md` — storyboards and timing templates for the recipes.
- `references/gotchas.md` — every mistake already made, so you don't repeat it.
- `scripts/` — `smallest_tts.py`, `smallest_stt.py`, `clone_voice.py`, `elevenlabs_tts.py`, `spectrum.py`, `envelope.py`, `placeholder_tts.sh`, `build_transcript.py`, `enhance_footage.py`, `phone_quad.py`. Keys come from environment variables and are never written to disk.
- `assets/` — Aeonik Pro Regular/Medium (licensed to Smallest; keep internal), `logo.png` (cream, for dark), `logo_black.png` (for light), `grain.png`, `gradient-bg.js` (moving gradient in any colours).
- `examples/` — finished compositions as working references.

## Credentials

Keys arrive in chat. Pass them inline as environment variables for one command; never write them into a file, a script, a log or a composition. Expect them to be rotated — a 401 `unauthorized` later means ask again.
